# Framecho Worker

Самостоятельно размещаемый сервис облачной публикации для [Framecho](https://github.com/helson-lin/Screendrop). Его поддерживает helson-lin. Основан на [Screendrop Worker](https://github.com/fayazara/screendrop-worker), сохраняет его протокол загрузки и добавляет снимки экрана, записи, обложки и превью.

Стек: TanStack Start / React / Kumo / Video.js, развёртывание на Cloudflare Workers. R2 хранит файлы, D1 — метаданные публикации.

Сервис отдаёт только страницы публикации и API. Адрес `/` отвечает 404. Логотип на странице ведёт в репозиторий Framecho.

Страница — одна спокойная колонка: заголовок, дата и медиа в исходных пропорциях. **Скачать** — единственная залитая кнопка. Рядом **Копировать Markdown**. Копирование ссылки и изображения, полный экран и масштаб (вписать / исходный размер, также по нажатию на изображение) находятся в меню «Ещё». На телефоне копирование ссылки тоже в этом меню и вызывает системную отправку, если браузер её поддерживает. Markdown для изображения использует адрес оригинала. Для записи используется обложка-ссылка, а если обложки нет — ссылка на страницу. Язык страницы берётся из браузера: упрощённый китайский, традиционный китайский, английский, русский, японский или корейский. Оформление следует светлой или тёмной теме системы.

Комментарии, отметки «нравится», счётчик просмотров и субтитры на странице больше не показываются. Их API и уже сохранённые данные остаются. Чтобы вернуть интерфейс, миграция данных не нужна.

Framecho по умолчанию загружает снимки как AVIF и прикладывает JPEG-обложку через `/api/assets/:id`. Если обложка есть, `og:image` / `twitter:image` используют её, и чаты, которые не умеют AVIF, всё равно показывают превью. Старые загрузки без обложки по-прежнему открывают оригинал.

## Развёртывание

1. Откройте **Framecho → Настройки → Облако** и нажмите **Скопировать токен и развернуть**. Framecho копирует токен загрузки и открывает страницу Cloudflare.
2. Эта страница клонирует репозиторий в ваш аккаунт GitHub. При первом развёртывании вставьте токен в **`UPLOAD_TOKEN`** (⌘V). Cloudflare создаёт R2 и D1.
3. Вставьте URL развёрнутого Worker обратно в Framecho и нажмите **Проверить соединение**. Приложение вызывает `/api/setup`, чтобы создать базу, затем `/api/ping`, чтобы проверить токен.

URL Worker — это адрес сервиса публикации, например `https://framecho-worker.<account>.workers.dev`. Это не домен бакета обоев. Обои и публикации снимков или записей могут использовать разные бакеты R2.

**Для загрузки и просмотра не нужны GitHub Application ID и OAuth.** OAuth нужен только API комментариев и отметок. Страница публикации этих двух функций сейчас не предлагает.

Развёртывание из командной строки:

```bash
git clone https://github.com/helson-lin/Framecho-worker.git
cd Framecho-worker
pnpm install --frozen-lockfile
cp .dev.vars.example .dev.vars
# Запишите свой UPLOAD_TOKEN в .dev.vars. Этот файл не коммитится.
pnpm run build
pnpm exec wrangler deploy --secrets-file .dev.vars
```

Первый запуск CLI может создать ресурсы. После этого сохраните настоящее имя Worker, `database_id` / `database_name` для D1 и `bucket_name` для R2 в `wrangler.jsonc` развёрнутого репозитория, чтобы следующие публикации использовали те же ресурсы. В этом шаблоне нет чужих идентификаторов ресурсов.

## Обновление уже развёрнутого Worker

Копия репозитория, созданная одной кнопкой, сама за этим репозиторием не следует. В развёрнутом репозитории создайте ветку, заберите обновления отсюда и просмотрите их. Сохраните имя Worker и привязки R2 / D1. После проверок влейте ветку в ветку публикации и дайте Workers Builds выпустить её.

Если у копии и этого репозитория нет общей истории, переносите код по частям или согласуйте истории в ветке. Не затирайте рабочую конфигурацию. Необязательные переменные и секреты остаются в Cloudflare и не должны попадать в репозиторий.

```bash
pnpm install --frozen-lockfile
pnpm run cf-typegen
pnpm run test
pnpm run typecheck
pnpm run lint
pnpm run build
```

После публикации обновления нажмите в Framecho **Проверить соединение**. `/api/setup` обновляет уже существующую базу на месте. Инициализация хранит версию схемы. Обычный запрос только сверяет версию и не выполняет DDL повторно. Параллельное обновление считает ошибку повторяющегося столбца уже применённым изменением. Старые 8-символьные идентификаторы публикаций продолжают работать. Новые используют 32 символа.

Живая база могла получить таблицы при инициализации во время работы. **Не запускайте историческую команду `db:migrate:remote` напрямую.** Старые шаги Drizzle по созданию таблиц и столбцов могут столкнуться с этой схемой. Это обновление не переносит и не удаляет уже лежащие файлы.

Запросы на слияние и отправка в `main` запускают те же тесты, проверку типов, lint и сборку в GitHub Actions (`.github/workflows/ci.yml`). В `main` можно влить изменения только после успешного **Test and build**.

Версия Worker хранится в `version.json`. `/api/version` возвращает её же. Framecho читает `version.json` на `main` этого репозитория, чтобы узнать, есть ли обновление.

## Необязательная конфигурация

| Параметр | Назначение |
| --- | --- |
| `UPLOAD_TOKEN` | Обязателен. Разрешает загрузку, инициализацию и удаление. |
| `AUTHOR_NAME` | Имя на странице публикации. Если не задано, не показывается. |
| `GITHUB_CLIENT_ID` / `GITHUB_CLIENT_SECRET` | GitHub **OAuth App** для входа в API комментариев и отметок. |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | Вход через Google OAuth. |
| `AUTH_SECRET` | Отдельный секрет подписи сессии. По умолчанию — токен загрузки. |

`optional-vars.example` перечисляет необязательные значения. Они не входят в обязательные секреты развёртывания одной кнопкой. В рабочей среде задайте их командой `pnpm exec wrangler secret put <NAME>`. Локально допишите их в `.dev.vars`: Git этот файл не отслеживает.

Адрес возврата GitHub OAuth: `https://<your-worker>/api/auth/callback/github`. Адрес возврата Google OAuth: `https://<your-worker>/api/auth/callback/google`. Сначала разверните Worker, затем создайте учётные данные у поставщика и запишите их в Worker. Если не настроено ни то ни другое, анонимных комментариев и отметок нет.

## API и данные

Управляющие запросы используют `Authorization: Bearer <UPLOAD_TOKEN>`.

| Путь | Метод | Назначение |
| --- | --- | --- |
| `/api/setup` | POST | Создать или обновить базу |
| `/api/ping` | GET | Проверить токен и соединение |
| `/api/version` | GET | Прочитать версию Worker |
| `/api/upload` | PUT / POST | Потоковая загрузка / multipart |
| `/api/register` | POST | Зарегистрировать медиа, уже лежащее в R2 |
| `/api/assets/:id` | POST | Загрузить обложку, субтитры, превью, заголовок или главы |
| `/api/upload/:id` | PUT / DELETE | Заменить эту публикацию на месте (ссылка та же) / удалить публикацию и её данные |
| `/:id` | GET | Публичная страница |

Потоковая загрузка принимает `X-Filename`, `X-Media-Type`, `X-Width`, `X-Height`, `X-Duration`, `X-Title` и `X-Social-Enabled`. Заголовок передаётся в процентном UTF-8. Неверная кодировка или параметры дают 400. Ответ: `{ id, url, filename, size }`. Размер — число байтов, которое записал R2.

Медиа по-прежнему пишется потоком. Новая загрузка использует условную запись R2 и не затирает уже существующий объект. `PUT /api/upload/:id` заменяет файл этой публикации и сохраняет id, комментарии и число просмотров. Если запись в D1 не удалась, новый объект удаляется. R2 и D1 — не одна транзакция, поэтому неудавшуюся из-за сети очистку всё ещё нужно завершить вручную. У заменённой страницы к адресу медиа добавляется `?v=`, чтобы браузер не продолжал показывать кэшированную копию.

`BUCKET` — это R2, `DB` — это D1. Любой, у кого есть ссылка, может смотреть и скачивать медиа. OAuth защищает только комментарии и отметки.

## Локальная разработка

Нужен Node.js 22 или новее. Проект закрепляет pnpm 12.8.1.

```bash
pnpm install --frozen-lockfile
cp .dev.vars.example .dev.vars
# Укажите локальный тестовый токен, не рабочий.
pnpm run cf-typegen
pnpm run dev
```

Сервер разработки: `http://localhost:3000`. R2 и D1 — локальные имитаторы. `pnpm run test` использует Miniflare из Wrangler этого проекта. Проверяются перенаправления, параметры загрузки, CORS, отказ R2 перезаписывать объект и очистка после сбоя, а также параллельное обновление D1 с сохранением старых строк.
